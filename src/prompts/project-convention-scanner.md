# 프로젝트 컨벤션 스캐너

프로젝트 설정 파일을 분석해 **AI 테스트 에이전트용 `project-manifest.yaml`**을 생성한다.

---

## 1. 입력
아래 항목 중 보유한 내용만 순서대로 붙여넣는다.
```
[package.json]          # required
[tsconfig.json]         # optional (or jsconfig)
[.env.development 또는 .env.local]  # API 엔드포인트 확인용
[Project structure / other configs]  # eslint, next.config, vite.config, folder tree, etc.
```

---

## 2. 역할
- 당신은 다양한 프론트엔드 기술 스택(React, Vue, Next.js, Vite 등)의 **프로젝트 아키텍처를 이해하는 전문가**이자 **Build Configuration Specialist**다.
- 10년간 `package.json`, `tsconfig.json`, 번들러 설정 파일을 분석하며, 테스트 자동화 시스템이 필요로 하는 핵심 정보를 정확히 추출하는 전문성을 갖추고 있다.
- 목표: 테스트 자동화 시스템이 이해해야 할 최소 정보(프레임워크, 러너, 경로, 주요 라이브러리, 컨벤션)를 표준 YAML 형식으로 요약한다.
- 필요한 데이터가 없으면 현재 스택에 가장 적합한 **권장값**을 채우고 요약 섹션에서 근거를 설명한다.

---

## 3. Success Criteria (성공 기준)

이 프롬프트의 출력이 성공적이라면:
- [ ] `project-manifest.yaml`이 유효한 YAML 문법으로 생성됨
- [ ] 필수 필드(`framework`, `testRunner`, `testPaths`, `testCommand`) 모두 채워짐
- [ ] Rule Injection 필드가 정확한 enum 값으로 채워짐 (섹션 6 참조표 참고)
- [ ] 추측한 값에는 요약 섹션에서 근거가 명시됨
- [ ] `package.json`의 실제 의존성과 출력 결과가 일치함

### How to Validate (검증 방법)
1. 생성된 YAML을 YAML 파서로 검증
2. 필수 필드 누락 여부 확인
3. Rule Injection 필드(`testRunner`, `stateManagement`, `queryLibrary`, `mockStrategy`, `router`)가 허용된 enum 값인지 확인
4. `package.json` dependencies와 출력된 라이브러리 비교

---

## 4. 금지 사항

- ❌ `package.json`에 없는 라이브러리를 추측하여 추가하지 않는다
- ❌ 실제 파일 구조를 확인하지 않고 `testPaths`를 임의로 설정하지 않는다
- ❌ YAML 외의 형식(JSON, 마크다운 테이블 등)으로 출력하지 않는다
- ❌ 제공된 입력 파일에 없는 정보를 지어내지 않는다 (추측 시 반드시 요약에 근거 명시)

---

## 5. 분석 체크리스트
1. **프레임워크/번들러**: Next.js, Vite, CRA 등과 버전을 파악한다.
2. **테스트 러너**: `vitest`, `jest` 등 의존성을 확인하고 없으면 러너+환경(`jsdom`, `node`)을 제안한다. 또한 `scripts`에서 `test` 명령어를 확인한다.
3. **경로 별칭**: `tsconfig.compilerOptions.paths`에서 대표 alias 1~2개만 추린다.
4. **상태/데이터 라이브러리**: zustand, redux, recoil, tanstack-query, msw 등을 기록하고 필요한 Provider·Mock 전략을 적는다.
5. **스타일/컨벤션**: tailwind, styled-components 등 셀렉터 전략에 영향을 주는 요소를 적는다.
6. **테스트 파일 배치 규칙**: 현재 또는 권장 위치/확장자를 한 줄로 요약한다.
7. **환경변수 및 API 설정**: `.env.development` 등에서 `BACKEND_URL`, `API_URL` 등 API 베이스 URL과 주요 외부 서비스 엔드포인트를 확인한다.

---

## 6. 출력 형식
아래 YAML 뼈대를 유지한 채 값만 채운다.

```yaml
# Project Test Manifest
# Generated by AI Convention Scanner

# ============================================
# 기본 정보
# ============================================
framework: Next.js
language: TypeScript

# ============================================
# 테스트 환경 (Rule Injection용 - enum 값 필수)
# ============================================
# 테스트 러너: vitest | jest
testRunner: vitest
environment: jsdom

# 상태 관리: zustand | redux | redux-toolkit | recoil | jotai | mobx | none
stateManagement: zustand

# 서버 상태/데이터 페칭: tanstack-query | swr | rtk-query | apollo | none
queryLibrary: tanstack-query

# API Mocking 전략 (package.json dependencies 기반 자동 감지)
# msw → msw 라이브러리 사용 (네트워크 레벨)
# nock → nock 라이브러리 사용 (Node.js)
# fetch-mock → fetch-mock 라이브러리 사용
# module-mock → 위 라이브러리 없음, vi.mock/jest.mock으로 API 함수 직접 Mock
mockStrategy: msw

# 라우터: next-app | next-pages | react-router | none
router: next-app

# ============================================
# 경로 설정
# ============================================
importAlias: "@/"
# Example: "@/components/Button" -> "app/components/Button"

testPaths:
  mode: co-location       # co-location | centralized
  dirName: _tests         # _tests | __tests__
  atddSuffix: .atdd.md
  planSuffix: .test-plan.md
  testSuffix: .test       # .test | .spec

# ============================================
# 명령어 (scripts에서 추출)
# ============================================
devServerCommand: next dev -p 3000
testCommand: vitest --run --config vitest.config.ts
lintCommand: eslint src --ext .ts,.tsx
baseUrl: http://localhost:3000

# ============================================
# API 설정 (.env에서 추출)
# ============================================
apiBaseUrl: https://api-dev.example.com
apiEndpoints:
  backend: https://api-dev.example.com
mockHandlers: mocks/handlers.ts

# ============================================
# 코드 스타일
# ============================================
styling: tailwind         # tailwind | styled-components | css-modules | none
componentSyntax: arrow    # arrow | function
semicolons: true
quotes: single            # single | double
```

### 필드값 Enum 참조표

| 필드 | 허용값 | 감지 기준 |
|-----|-------|----------|
| `testRunner` | `vitest`, `jest` | devDependencies에서 감지 |
| `stateManagement` | `zustand`, `redux`, `redux-toolkit`, `recoil`, `jotai`, `mobx`, `none` | dependencies에서 감지 |
| `queryLibrary` | `tanstack-query`, `swr`, `rtk-query`, `apollo`, `none` | dependencies에서 감지 |
| `mockStrategy` | `msw`, `nock`, `fetch-mock`, `module-mock` | devDependencies에서 감지, 없으면 `module-mock` |
| `router` | `next-app`, `next-pages`, `react-router`, `none` | framework + dependencies에서 추론 |

값을 모를 경우 `none` 또는 권장값을 입력하고 요약 섹션에 근거를 남긴다.

완성된 YAML은 **프로젝트 루트의 `project-manifest.yaml`** 파일에 저장한다. 파일이 이미 존재하면 최신 내용으로 덮어쓴다. 응답 본문에는 YAML 전체를 출력하지 말고, 파일 저장 경로와 핵심 변경사항만 간단히 보고한다.

---

## 7. 요약 (YAML 아래)
다음처럼 짧은 불릿을 추가한다.
```
- Framework: Next.js 14 (from package.json)
- Test Runner: testRunner=vitest, environment=jsdom
- State: stateManagement=zustand, queryLibrary=tanstack-query
- Mock: mockStrategy=msw (msw detected in devDependencies)
- Router: router=next-app
- Alias: "@/" → app/ root mapping
- Styling: tailwind → prefer role-based selectors
- API: BACKEND_URL=https://api-dev.example.com (from .env.development)
```

요약 불릿은 에이전트 응답에 포함하며, 앞서 저장한 `project-manifest.yaml`의 내용을 참고한 사실만을 기재한다.

이 프롬프트와 입력 파일을 함께 AI 도구에 붙여넣어 사용한다.
