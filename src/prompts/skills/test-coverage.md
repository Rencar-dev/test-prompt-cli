# test-coverage

**이 skill은 /self-learn 후, /test-verify 전에 실행됩니다.**

---

## 목적

ATDD 시나리오와 테스트 코드 간의 **추적성(Traceability)**을 검증합니다.
Plan에 정의된 모든 시나리오가 실제로 구현되었는지 확인하여 누락을 방지합니다.

---

## 실행 절차

### 1단계: Plan 파일에서 시나리오 ID 추출

Test Plan 파일(`.test-plan.md`)에서 시나리오 ID를 추출합니다:

```markdown
## Plan 파일 예시
| ID | 시나리오 | Type |
|----|----------|------|
| S1 | 유효한 자격 증명으로 로그인 | E2E→Integration |
| S2 | 온보딩 미완료 시 온보딩 화면 이동 | Integration |
```

**분기 조건 확인**:
- Plan에 "분기 조건", "별도 테스트 케이스로 분리" 등의 언급이 있으면 해당 시나리오의 서브 ID도 추출
- 예: S1에 분기 2개 → `S1-1`, `S1-2` 필요

**추출 결과 예시**:
```
Plan 시나리오: S1-1, S1-2, S2, S3, S4-1, S4-2, S4-3, S5, S6-1, S6-2, S7, S8, S9, S10, S11, S12, S13
```

### 2단계: 테스트 파일에서 구현된 ID 추출

테스트 파일(`.test.tsx`)의 `it` 블록에서 시나리오 ID를 추출합니다:

```typescript
// 테스트 파일 예시
it('[S1-1] 폼 타입 사용자가 유효한 자격 증명으로 로그인...', async () => { ... });
it('[S1-2] 파트너 타입 사용자가 유효한 자격 증명으로 로그인...', async () => { ... });
it('[S2] 로그인 성공 후 온보딩 미완료 시...', async () => { ... });
```

**추출 패턴**: `it\('[[]([A-Z]\d+(?:-\d+)?)[]]`

**추출 결과 예시**:
```
구현된 시나리오: S1-1, S1-2, S2, S3, S4-1, S4-2, S4-3, S5, S6-1, S6-2, S7, S8, S9, S10, S11, S12, S13
```

### 3단계: 커버리지 비교

| 검증 항목 | 설명 |
|-----------|------|
| 누락된 시나리오 | Plan에 있지만 테스트에 없는 ID |
| 추가된 시나리오 | 테스트에 있지만 Plan에 없는 ID (확인 필요) |
| 분기 누락 | Plan에 분기 조건이 있지만 서브 ID가 없는 경우 |

### 4단계: 누락 시 조치

**누락이 있는 경우**:
1. 누락된 시나리오 ID 목록 출력
2. 해당 시나리오의 Plan 내용 참조하여 TODO 블록 추가
3. test-implementer agent에게 추가 구현 위임

**누락이 없는 경우**:
- "모든 시나리오가 구현되었습니다" 출력 후 /test-verify로 진행

---

## 출력 형식

### 커버리지 100% 달성 시

```
## test-coverage 검증 결과

### 시나리오 커버리지
- Plan 시나리오: 17개
- 구현된 테스트: 17개
- 커버리지: 100% ✅

### 상세 매핑
| Plan ID | 테스트 ID | 상태 |
|---------|-----------|------|
| S1-1 | [S1-1] | ✅ |
| S1-2 | [S1-2] | ✅ |
| S2 | [S2] | ✅ |
| ... | ... | ... |

---
→ 모든 시나리오가 구현되었습니다. /test-verify를 실행하세요.
```

### 누락이 있는 경우

```
## test-coverage 검증 결과

### 시나리오 커버리지
- Plan 시나리오: 17개
- 구현된 테스트: 15개
- 커버리지: 88% ⚠️

### 누락된 시나리오
| ID | 시나리오 | Plan 참조 |
|----|----------|-----------|
| S6-2 | Error 110 - 계정 없음 | "S6-2: Error 110 - 계정 없음 (대체 코드)" |
| S12 | Enter 키 로그인 제출 | "비밀번호 입력 후 Enter 키를 누르면 로그인 제출" |

### 조치 필요
- 위 시나리오에 대한 테스트 구현이 필요합니다.
- test-implementer agent에게 추가 구현을 위임하거나 직접 구현하세요.

---
→ 누락된 시나리오를 구현한 후 다시 검증하세요.
```

### 분기 누락 경고

```
## test-coverage 검증 결과

### 시나리오 커버리지
- Plan 시나리오: 17개
- 구현된 테스트: 16개
- 커버리지: 94% ⚠️

### 분기 누락 경고
| 시나리오 | Plan 분기 조건 | 현재 구현 |
|----------|----------------|-----------|
| S1 | "폼 타입 vs 파트너 타입" → S1-1, S1-2 필요 | S1만 존재 |

### 조치 필요
- S1을 S1-1, S1-2로 분리하여 각 분기를 별도 테스트로 구현하세요.

---
→ 분기 조건을 분리한 후 다시 검증하세요.
```
